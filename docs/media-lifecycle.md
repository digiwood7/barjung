# 사진 수명주기

## 저장

매물 사진 원본은 Supabase를 경유하지 않는다. 관리자가 저장을 누르면 브라우저가 고객 PC의 Windows 실행기(`127.0.0.1:43127`)에 원본을 전달한다. 실행기는 로컬 Python으로 사진을 한 장씩 축소하고 EXIF를 제거한 JPEG만 `property-media` 버킷에 업로드한다.

`property-media-staging`과 `media_optimization_jobs`는 이전 배포와 진행 중이던 작업을 호환하기 위해 남아 있지만 신규 웹 업로드에서는 사용하지 않는다. 안정화 후 별도 마이그레이션으로 제거할 수 있다.

## 플랫폼 발행

플랫폼 어댑터는 Supabase 사진 URL을 게시물에 연결하지 않는다. 발행 직전에 최적화 파일을 고객 PC로 내려받고 네이버·인스타그램 등의 업로드 입력에 파일 자체를 전송한다. 따라서 플랫폼 발행이 성공한 뒤 Supabase 사진이나 과거 매물 DB를 삭제해도 이미 게시된 플랫폼 사진에는 영향이 없어야 한다. 새 플랫폼 어댑터도 반드시 이 원칙을 따른다.

## 삭제

매물 삭제 시 해당 `office_id/property_id/` 범위로 검증된 최종 사진과 구형 임시 사진만 Storage에서 먼저 제거한 뒤 매물 DB 행을 삭제한다. 매물 행 삭제는 관련 고지사항, 원고, 발행 작업 및 사진 메타데이터를 외래 키 연쇄 삭제한다. 외부 플랫폼 게시물은 별도 자산이므로 자동 삭제하지 않는다.
